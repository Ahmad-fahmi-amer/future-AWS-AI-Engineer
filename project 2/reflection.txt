Project Reflection

One important design decision I made was to keep each capability behind the project’s intended AgentCore integration instead of asking the model to perform the work itself. Order tracking and refunds are exposed through the AgentCore Gateway using MCP, product and policy questions are grounded through the Bedrock Knowledge Base, loyalty calculations use AgentCore Code Interpreter, and live web requests use AgentCore Browser. This separation keeps backend data and deterministic operations outside the model and makes tool results the source of truth.

The most significant challenge I encountered was the Browser integration on Python 3.14. After a Browser invocation, later runtime invocations could fail with a weak-reference error inside AnyIO. Investigation showed that the Browser implementation called nest_asyncio.apply(), which caused asyncio.current_task() to become None in this environment. I reproduced the behavior locally, tested nest-asyncio2, and added a compatibility shim before importing Strands so the Browser implementation uses the compatible module. After redeployment, repeated Browser and health invocations completed successfully. During final evidence collection, the Browser request was slow but CloudWatch confirmed that it completed successfully, and I manually terminated the remaining Browser session.

For production, I would strengthen security, reliability, observability, and cost control. IAM permissions should be narrowed to the smallest supported resources, especially Browser permissions. I would add structured output validation, explicit timeouts and retry policies around external integrations, and lifecycle handling for Browser sessions. CloudWatch metrics and alarms should be connected to operational notifications and dashboards. I would also monitor token usage, Knowledge Base retrieval quality, Code Interpreter usage, Browser duration, and memory retention so that latency and cost can be controlled as traffic grows.
